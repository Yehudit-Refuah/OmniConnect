Automated Appointment Confirmations & Reminders

Guidelines & Requirements Summary

This document summarizes the requirements discussed for the automated day-prior confirmation and same-day reminder component. Items marked for confirmation in the final section need client sign-off before build.

Recognized responses
| Outcome       | Recognized keywords / phrases                                                              | Action |

Reschedule routing
• Ask the patient whether to cancel the appointment regardless of the next available opening or keep it in place while seeking another opening.

Day-prior confirmation

| Channels              | Calls and texts work in conjunction; a response on one channel updates the status and is not overridden by the other |

Same-day reminder
| Timing                 | 1.5 hours prior to the appointment |
| Applicable eCW statuses| All appointment statuses |
| Purpose                | Courtesy reminder |

A centralized management dashboard and audit logging interface providing clinical managers, supervisors, and operations teams with real-time visibility and historical tracking for every patient visit and communication touchpoint.

Visit Journey Audit Trail (Chronological Log)

• Initial Appointment Record: Appointment booked/modified in eCW, provider assigned, specialty, and location.

## 4. Claude's analysis of the requirements

**Proposed architecture:**
```
eCW ──(read appointments)──► Sync service ──► PostgreSQL (appointments, audit log)
   Scheduler: 9:00 AM day-prior batch (PENDING only) + same-day reminder 1.5 h before (all statuses)
   Rules engine: family grouping, exclusions, Spanish, late/new-patient arrival times, no-show notice
   Channels: outbound voice (TTS, voicemail detection, keypad/speech) | two-way SMS | inbound callback
   Status write-back to eCW (CONFPHONE, CANCSMS, MSNGRVCMSG, ...)
   Transfers to queues x1100 / x1301 / x7724 / x1160 with wait-time estimates
   Manager dashboard (React): search, live counts, at-risk alerts, visit timeline, CSV/Excel export
```
This component works mostly from fixed rules and doesn't need an LLM. AI would only help with understanding free-text SMS or speech replies that don't match the keyword list.

**Technical facts needed from Refuah:** eCW API read and write access (custom status codes); which PBX handles the extensions; how Dental, Optical and WH are identified in eCW; the queue reports for the wait-time estimates.

**Gaps and contradictions found in the requirements:**

4. Exact retry times and the maximum number of attempts
5. Rescheduling by SMS: a text can't be transferred to reception

8. Callback identity verification method
9. Unclear replies ("maybe", "running late")

## 6. Database is SQL Server (2026-11-08, new session)

**Note:** the project folder is actually `C:\Users\ygarbuz\Projects\OmniConnect`, and the SQL files and `PLAN.md` are in `db\ecw\`.

**User:** my db is ssms are there any changes?

**Claude:** the eCW database is Microsoft SQL Server (accessed with SSMS), not MySQL. Both SQL files are converted to T-SQL (v0.2) and `PLAN.md` is updated. The logic is unchanged. Syntax changes:
- `SHOW COLUMNS` / `SHOW INDEX` → `INFORMATION_SCHEMA.COLUMNS` / `sys.indexes`
- `DATABASE()`, `VERSION()` → `DB_NAME()`, `SERVERPROPERTY(...)`, `@@VERSION`
- `CURDATE() ± INTERVAL` → `DATEADD(DAY, n, CAST(GETDATE() AS date))`
- `SET @x =` → `DECLARE @x type =`
- `LIMIT 5` → `TOP (5)`
- `TIMESTAMPDIFF(YEAR)` → exact age calculation with `DATEDIFF` + `TRY_CONVERT` (dob may be stored as text)
- `CAST(... AS CHAR)` → `CAST(... AS varchar(50))`
- Tomorrow filter is a half-open range (`>= @target_date AND < @next_date`), which works for both date and datetime columns and keeps index use
- Added `SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED` so the extract doesn't block eCW users
- `CONCAT_WS` needs SQL Server 2017+

**New open questions:** is the database the live eCW database or a reporting copy (and how current is it)? What is the SQL Server version?
