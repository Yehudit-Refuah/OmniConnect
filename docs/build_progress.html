3. What happens when someone opens /api/pbx/v1/calls

Following one request from start to finish.

  1. The caller sends a GET request to http://localhost:8000/api/pbx/v1/calls?limit=50. Today that's you, clicking "Try it out" on the /docs page. Later it will be the PBX.
  2. FastAPI looks up the address. main.py plugged in the PBX router with include_router, so FastAPI knows that /api/pbx/v1/calls belongs to get_calls() in router.py.
  3. get_calls() runs. It takes up to limit calls from FAKE_CALLS and wraps them in a CallBatch with a batch ID and the current time.
  4. The models check the data. Because of response_model=CallBatch, FastAPI checks every field against models.py: names, types, dates. A missing or wrong field becomes an error on our side, so the PBX never gets a broken answer.
  5. The caller gets JSON back, in exactly the layout promised to the PBX team in PBX_INTEGRATION_API.md §4.1.

4. The shape of the call list (models.py)

Each box holds the boxes inside it. One call can cover a whole family, and one patient can have more than one appointment.

6. ⚠️ One fix before committing B2

In main.py, the router lines come before the app exists

Python reads a file from top to bottom. app.include_router(...) uses app, but app is only created a few lines later. So the server stops with NameError: name 'app' is not defined.
The fix: move app.include_router(pbx_router) to after app = FastAPI(...). The import line can stay at the top. 
✗ Now
from fastapi import FastAPI

from app.pbx.router import router as pbx_router

app.include_router(pbx_router)   # app doesn't exist yet

app = FastAPI(title="OmniConnect API")
✓ Fixed
from fastapi import FastAPI

from app.pbx.router import router as pbx_router

app = FastAPI(title="OmniConnect API")
app.include_router(pbx_router)   # now app exists
