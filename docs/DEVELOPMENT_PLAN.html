1What we're building

Every day the system runs six steps. The same platform later carries Phases 1, 2, 4 and 5. Phase 3 comes first because it's mostly fixed rules, has clear value, and needs no AI.

1
📥

Read

Tomorrow's PENDING appointments from eCW

2
🧠

Decide

Family grouping, Spanish, arrival times, Shabbat rule

3
📞

Contact

Call + text, voicemail, afternoon & evening retries

4
💬

Understand

Confirm, cancel or reschedule; transfer to reception

5
🔁

Write back

CONFPHONE, CONFSMS, CANCPHONE … into eCW

6
📊

Show

Manager dashboard with a full audit trail

🛡️
Guiding principle: the system never contacts a real patient until a step has been tested, reviewed and deliberately switched on (shadow mode, then allowlist mode, then pilot).

Daily flow

  1. 19:00 AM: is today a run day?Worker · no-contact calendar
  2. 2Run the day-prior query on eCW and save a snapshotWorker → eCW
  3. 3Build contact groups, messages and the scheduleRules engine
  4. 4For each group: re-check status (still PENDING?) and check the send time is allowed (Shabbat/holiday)Worker
  5. 5Call + text the patient; the provider reports the result by webhookProvider → API
  6. 6Parse the reply → outcome → status code, write to eCW, log in the audit trailAPI → eCW
  7. 7Afternoon + evening retries for anyone not reachedWorker

9Security & HIPAA rules for development

These apply from day one, including while you're learning.

No PHI in Git, ever

No real names, phones, MRNs, results, screenshots or exports. If PHI is committed by mistake, tell IT/compliance right away; deleting it in a new commit is not enough.

Secrets live in .env only

Never committed. .env.example shows the names with fake values.

Test with fake data

"Test Patient", 555-0100 numbers. Real data only in shadow mode on the server.

Least privilege

Read-only access to eCW; each dashboard role sees only what it needs.

Logs have no PHI

Log appointment IDs, not names or phone numbers.

Audit everything

Every contact, response, status change, staff timeline view and export.

Protected main branch

Private repo; changes only through pull requests; secret scanning on.
